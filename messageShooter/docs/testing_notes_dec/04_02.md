# Step by step testing guide of the feature

@ core
1) create contacts
2) create messages
3) register phones

@ messageShooter
1) create campaigns linked to contacts
2) process campaigns
3) check results at target lists
4) verify the counters at target lists
5) add target lists to queue
6) process queue

@ key features
1) 1x queue = 1x token
2) multiple queues can be processed at the same time with async callsc
3) 8 second interval between target list recipients
4) sequential message order according to counter from logs

@ doubts
1) should I save the target list? thinking about having them temporarily / 24h
2) should I save the queues? thinking about having them temporarily / 24h
3) how can we think about queues receiving leads data?
- queue <> loja <> token

a. webhook
b. rota pending leads

@ one phrase explanation 
services:
- queue_processor.py = async message processor with rate limiting and concurrent queue handling
- scheduler.py = campaign scheduler that creates and manages target lists and queues

resolvers:
- get_contacts.py = get contacts from Core according to contact type (whatsapp, appointment) and tag
- get_message.py = get message from Core according to contact tag and counter
- get_userphone.py = get userphone from Core according to contact tag
- get_counter.py = get counter from Core according to sent messages and contact tag

- target_list_resolver.py = manages target list creation and contact association for campaigns
- queue_resolver.py = process individual queue entries with retry logic and status tracking

signals:
- update counter when generating target list
